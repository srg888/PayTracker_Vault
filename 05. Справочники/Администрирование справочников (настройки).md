# Администрирование справочников (раздел «Настройки»)

> Задача поставлена пользователем (Сергеем) в чате, не из [[Заметки на будущее|заметок]]. Статус: ❌ не реализовано — сейчас в разделе «Настройки» есть только загрузка CSV (`/settings/import`), без просмотра, редактирования или удаления существующих записей. Эта секция — техническое задание для реализации, достаточно детальное, чтобы по нему можно было писать код без дополнительных уточнений.

## Что есть сейчас

### Таблицы-справочники в БД (реальные, редактируемые)

|---|---|---|---|---|
| Подразделения | `Division` | `id` (уникален `name`) | `name` | — (отдельного файла в vault пока нет) |
| Валюты | `Currency` | `id` (уникален `code`, ISO 4217) | `code` | [[Список валют]] |
| Курсы валют (не справочник, а кэш данных по справочнику «Валюты») | `ExchangeRate` | `id`, уникальность `(currency_id, rate_date)` | `rate_date`, `rate_value`, `source`, `is_stale` | [[Список валют]] |

| Типы документов | `DocumentType` | `code` (сам PK) | `name`, `category`, `is_required_default`, `recipient_service` | [[Справочник типов документов]], [[Службы-получатели документов]] |

**Важное уточнение по формулировке задачи:** «способ оплаты» (наличные/банк/карта и т.п., `PaymentMethod`) — это **не таблица БД**, а зашитый в код Python-enum (`app/models/enums.py`). Его нельзя редактировать через CRUD-страницу без изменения кода и миграции — если нужно сделать его управляемым справочником, это отдельная, более серьёзная задача (перевод enum в таблицу БД со всеми зависимыми местами, где он используется — `PaymentTermsProposal.proposed_payment_method`, `PaymentExecution.method`). Ниже эта задача не включена в scope, но отмечена как отдельный пункт на будущее.

### Что уже есть для импорта (переиспользовать, не дублировать)
`app/services/import_refs.py` + роут `POST /settings/import` (форма на `settings/import.html`) — на сегодня умеет **upsert по ключу** (добавить новое / обновить существующее по коду или имени) для: `import_agents`, `import_buyer_companies`, `import_exchange_rates`. **Нет** `import_divisions` и `import_document_types` — при реализации этой задачи стоит дописать и их, по той же сигнатуре `(db: Session, file: BinaryIO) -> dict`, для единообразия. Удаления через CSV-импорт нет и не должно появляться (риск случайно затереть справочник пустым/неполным файлом) — удаление только через явный UI, см. ниже.

## Предложение по архитектуре (рекомендуемый вариант)

Вместо пяти отдельных вручную написанных страниц (по одной на справочник) — **одна универсальная CRUD-страница**, параметризованная ключом справочника. Обоснование: все пять справочников — плоские таблицы из 2–6 простых полей (строка/bool), логика просмотра/редактирования/удаления/bulk-удаления для них идентична, разница только в наборе колонок. Отдельные страницы на каждый справочник — это 5x дублирование одного и того же кода ради косметики; при появлении шестого справочника (а судя по `AGENTS.md`/`Agent`-докстрингу — «полное расширение справочника агентов запланировано отдельно» — новые поля/справочники будут появляться) его придётся снова писать с нуля.

### Реестр справочников
Новый модуль `app/services/reference_admin.py` с декларативным реестром:
```python
from dataclasses import dataclass, field
from typing import Any, Callable

@dataclass
class ReferenceField:
    name: str
    label: str
    type: str  # "str" | "bool" | "enum"
    editable: bool = True
    required: bool = False

@dataclass
class ReferenceSpec:
    key: str                    # "agents", "buyer_companies", "divisions", "currencies", "document_types"
    label: str                  # "Платёжные агенты"
    model: type
    pk_field: str                # "id" или "code" (для DocumentType)
    fields: list[ReferenceField]
    import_fn: Callable | None = None     # существующая import_agents и т.п., None если ещё не написана
    usage_check: Callable[[Session, Any], int] | None = None  # считает, сколько Request/RequestDocument ссылаются на запись

REFERENCE_REGISTRY: dict[str, ReferenceSpec] = {
    "divisions": ReferenceSpec(
        key="divisions", label="Подразделения", model=Division, pk_field="id",
        fields=[ReferenceField("name", "Название", "str", required=True)],
        usage_check=lambda db, obj: db.query(Request).filter(Request.division_id == obj.id).count(),
    ),
    "currencies": ReferenceSpec(
        key="currencies", label="Валюты", model=Currency, pk_field="id",
        fields=[ReferenceField("code", "Код (ISO 4217)", "str", required=True)],
        usage_check=lambda db, obj: db.query(Request).filter(Request.currency_id == obj.id).count(),
    ),
    "buyer_companies": ReferenceSpec(
        key="buyer_companies", label="Компании-покупатели", model=BuyerCompany, pk_field="id",
        fields=[
            ReferenceField("name", "Название", "str", required=True),
            ReferenceField("is_active", "Активна", "bool"),
        ],
        import_fn=import_buyer_companies,
        usage_check=lambda db, obj: db.query(Request).filter(Request.buyer_company_id == obj.id).count(),
    ),
    "agents": ReferenceSpec(
        key="agents", label="Платёжные агенты", model=Agent, pk_field="id",
        fields=[
            ReferenceField("code", "Код", "str", required=True),
            ReferenceField("name", "Название", "str"),
            ReferenceField("is_resident", "Резидент", "bool"),
            ReferenceField("is_active", "Активен", "bool"),
            ReferenceField("is_own_company", "Наша компания", "bool"),
        ],
        import_fn=import_agents,
        usage_check=lambda db, obj: (
            db.query(Request).filter(or_(Request.agent_id == obj.id, Request.subagent_id == obj.id)).count()
        ),
    ),
    "document_types": ReferenceSpec(
        key="document_types", label="Типы документов", model=DocumentType, pk_field="code",
        fields=[
            ReferenceField("name", "Название", "str", required=True),
            ReferenceField("category", "Категория", "enum", required=True),
            ReferenceField("is_required_default", "Обязателен по умолчанию", "bool"),
            ReferenceField("recipient_service", "Служба-получатель", "str"),
        ],
        usage_check=lambda db, obj: db.query(RequestDocument).filter(
            RequestDocument.document_type_code == obj.code
        ).count(),
    ),
}
```
Это не предписание дословного кода (конкретные импорты/сигнатуры могут отличаться) — предписание **подхода**: один реестр, одна страница, вместо пяти копипаст-страниц.

### Роуты (все — только для Руководителя, та же проверка `_require_rukovoditel`, что и у текущего `/settings`)
- `GET /settings/references` — список справочников из реестра с количеством записей в каждом (карточки/таблица со ссылками).
- `GET /settings/references/{key}` — таблица записей выбранного справочника: все поля из `fields`, чекбокс в начале строки, колонка «Используется в N заявках» (из `usage_check`), кнопка «Редактировать» на строку, кнопка «Добавить запись».
- `POST /settings/references/{key}/create` — создать новую запись (валидация `required`-полей на сервере).
- `POST /settings/references/{key}/{pk}/update` — обновить запись.
- `POST /settings/references/{key}/{pk}/delete` — удалить одну запись.
- `POST /settings/references/{key}/bulk_delete` (`ids: list[str] = Form(...)`) — удалить несколько отмеченных записей за один запрос/одну транзакцию.
- CSV-загрузку **не дублировать** новым роутом — на странице `/settings/references/{key}` достаточно ссылки/кнопки на существующий `/settings/import` с предвыбранным `reference={key}` (добавить таким образом, чтобы `import.html` принимал параметр предвыбора через query-string).

### Защита от удаления используемых записей (обязательно, иначе легко сломать исторические заявки)
Перед любым `delete`/`bulk_delete`:
1. Вызвать `usage_check(db, obj)` для каждой записи.
2. Если результат > 0 — **запретить** удаление этой записи (вернуть ошибку с текстом «Запись используется в N заявках, удаление запрещено»); для справочников с полем `is_active` (`Agent`, `BuyerCompany`) в этом случае предложить вместо удаления деактивировать (`is_active = False` — запись перестаёт предлагаться при создании новых заявок, но не ломает исторические).
3. Для `DocumentType` и `Division`/`Currency` (у которых нет `is_active`) — при попытке удалить используемую запись рекомендация такая же (запретить), но деактивации для них сейчас не предусмотрено: если это часто будет возникать на практике — отдельной задачей добавить `is_active` и этим справочникам (сейчас не добавляю, чтобы не расширять scope без необходимости — Руководитель может решить, что это не нужно, т.к. состав типов документов/валют/подразделений меняется редко).
4. Bulk-удаление — транзакционно: либо удаляются все отмеченные незанятые записи и по занятым выводится отдельный список «не удалено, т.к. используется», либо (более строгий вариант) всё удаление отменяется, если хотя бы одна из отмеченных записей занята, и явно показывается, какая — **выбор одного из двух вариантов — на усмотрение разработчика/Руководителя, в заметке зафиксировать, какой выбран**.

### Аудит
Новые значения `AuditActionType`: `REFERENCE_CREATED`, `REFERENCE_UPDATED`, `REFERENCE_DELETED` — пишутся в `AuditLog` с `entity_type=<ключ справочника>`, `entity_id=<pk>`, `field_name`/`old_value`/`new_value` для `update` (по аналогии с тем, как уже логируются другие действия в [[Аудит]]). Сейчас изменения справочников вообще нигде не логируются (ни текущий импорт, ни единственный существующий `toggle_document_requirement` для них) — это тоже закрывается данной задачей.

### UI
- Пункт меню в разделе «Настройки»: «Справочники» рядом с существующим «Импорт».
- Таблица на `/settings/references/{key}`: редактирование полей — либо инлайн (клик по ячейке → редактируемое поле, автосохранение/кнопка «Сохранить» в строке), либо через модальное окно «Редактировать запись» — на усмотрение реализации, инлайн предпочтительнее для таких простых справочников (меньше кликов на частую операцию типа «деактивировать агента»).
- Чекбоксы слева + «выбрать все» в шапке + кнопка «Удалить выбранные (N)», активная только когда выбрана хотя бы одна строка.
- Над таблицей — ссылка «Загрузить CSV» → `/settings/import?reference={key}` (переиспользует существующий механизм).
