# Критическая уязвимость nginx — «nginx2root» (раскрыта 18–19 ноября 2026)

> Приоритет — **выше**, чем [[Отдельный внешний листенер для PayTracker]]. Это неаутентифицированный RCE в самом nginx, который на этом сервере обслуживает всё: сайты-прикрытия Xray, teaPot, и скоро будет обслуживать внешний доступ к PayTracker. Патчить нужно независимо от того, когда (и будет ли) делаться отдельный листенер — и желательно ДО того, как добавлять новую внешнюю точку входа, а не после.

## Что это
«nginx2root» — пять уязвимостей в nginx, раскрытые исследователями Xint 18–19 ноября 2026, патч выпущен F5 в тот же день. Разрешают **неаутентифицированное** удалённое выполнение кода в контексте worker-процесса nginx; как минимум одна (CVE-2026-123007) существует с 2015 года (с версии 1.9.5) и, по оценке исследователей, на момент раскрытия была воспроизводима на ~99% хостов с определяемой версией nginx. Публичный PoC уже есть.

| CVE | Компонент | Что именно | Условие срабатывания |
|---|---|---|---|
| **CVE-2026-123007** («NGINX2Shell») | HTTP/2 flow control | integer underflow → повреждение памяти в куче | `http2` включён |
| CVE-2026-123633 | HTTP/2 проксирование на backend | use-after-free | `http2` + проксирование запросов на backend |
| CVE-2026-121810 | HTTP/3 / QUIC | use-after-free | `http3`/QUIC включён |
| CVE-2026-123634 | DNS resolver + subrequests | use-after-free | переменная в адресе проксирования + SSI/mirror-сабреквесты, резолвящие одно имя |
| CVE-2026-113425 | Mail proxy, `auth_http` | use-after-free | используется почтовый прокси nginx |
| CVE-2026-118899 (сопутствующая, high) | чтение тела запроса по TLS 1.3 | worker уходит в бесконечный цикл | DoS, без RCE |

На момент раскрытия (19.11.2026) ни одна не отмечена как эксплуатируемая «в дикой природе» и не в CISA KEV — но публичный PoC для CVE-2026-123007 уже есть (Rapid7), так что это вопрос времени, не «если».

## Исправленные версии
- **nginx Open Source**: `1.30.7` (stable) и `1.31.9` (mainline), выпущены 18.11.2026.
- Официальные Docker-образы `nginx` на Docker Hub — теги `1.30.7`/`1.31.9`, а также обновлённые `mainline`/`stable`/`latest` (если у вас этот сервис через Docker — то же самое правило: подтянуть образ недостаточно, нужно пересоздать контейнер).
- NGINX Plus: `R36 P4` / `R35 P2` / `R32 P6` и новее; ветки R34–R36 без отдельного патча — только переход на пропатченную ветку (вряд ли относится к этому серверу, но проверь).

## Что сделать

### 1. Выяснить, как у вас установлен nginx
`nginx -v` — узнать текущую версию. Если это системный пакет (apt/dnf) — патчить через пакетный менеджер; если в Docker-контейнере — через образ. На этом сервере teaPot/Xray и остальные сайты, видимо, идут через nginx как системный сервис — уточни по факту, не предполагай.

### 2. Проверить, что из уязвимого реально используется
```
nginx -T | grep -nE 'http2|http3|quic|resolver|mirror|ssi|auth_http|mail'
```
У вас точно включён `http2` (иначе не работал бы HTTPS с современными браузерами на ваших сайтах) — то есть CVE-2026-123007 и, возможно, CVE-2026-123633 применимы. HTTP/3 и mail proxy — скорее всего нет, но проверь, не угадывай.

### 3. Обновить и перезапустить (не reload!)
- Debian/Ubuntu (пакет из репозитория nginx.org, если подключён): `apt-get update && apt-get install --only-upgrade nginx` (или `nginx-common`, в зависимости от того, как ставили).
- Если ставили из дистрибутивного репозитория — `apt update && apt upgrade`, проверить версию патча для вашего релиза именно в security-advisory дистрибутива (не nginx.org) — патч может называться иначе/иметь другой номер версии при бэкпорте.
- Docker: подтянуть образ `1.30.7`/`1.31.9` и **пересоздать** контейнер(ы), не просто `docker pull` — старый контейнер продолжит работать на старом бинарнике.
- **Обязательно `restart`, не `reload`** — `nginx -s reload` оставляет старые worker-процессы со старым (уязвимым) кодом работать до естественного завершения; нужен полный перезапуск master-процесса.

### 4. Если прямо сейчас обновить нельзя (временная мера, не замена патчу)
`http2 off;` во всех `server`-блоках, где это возможно без потери нужной функциональности — закрывает CVE-2026-123007/123633 (условие срабатывания — включённый http2), но не остальные три. Это снижение риска на время, не постоянное решение — обновиться всё равно нужно.

## Обязательная проверка после (та же дисциплина, что и в [[Аутентификация и защита от перебора пароля|предыдущем развёртывании]])
Один nginx обслуживает несколько разных вещей на этом сервере — после рестарта проверить **все**, не только то, что патчили:
- teaPot — отвечает (сверить порт по факту, см. примечание в [[Отдельный внешний листенер для PayTracker]] про расхождение `9200`/`12425` в записях).
- Xray inbound'ы `8445`/`8447`/`8449` — живы, вход через VPN-туннель работает.
- Сайты-прикрытия nginx `8444`/`8446`/`8448` — отдают 200.
- `v.uk.remote-fitness.online:443` (PayTracker через `dokodemo-door`) — вход по-прежнему работает.
- `nginx -v` / `dpkg -l nginx` после рестарта показывает версию ≥ 1.30.7 (stable) или ≥ 1.31.9 (mainline) — не просто «команда отработала без ошибок», а именно сверить номер версии на выходе.

Если что-то не проходит — не чинить по живому, откат из бэкапа (см. процедуру бэкапа конфигов в [[Отдельный внешний листенер для PayTracker]] — та же дисциплина: бэкап перед изменением, обязателен).
